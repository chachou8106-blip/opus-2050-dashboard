## Pourquoi le garde-fou n'a pas joué

Le champ du 208 est :

```
{{trim(replace(replace(replace(replace(ifempty(207.data.candidates[1].content.parts[1].text; "{}"); "```json"; emptystring); "```"; emptystring); newline; emptystring); tab; emptystring))}}
```

`ifempty` ne protège que du **vide**. Une réponse vide devient `{}` et le run continue.
Une réponse **présente mais malformée** passe telle quelle dans ParseJSON, qui casse.
Les cinq Sages ont exactement le même montage (202, 204, 206, 208, 210) : la même
panne peut venir de n'importe lequel.

Et dans tout le scénario, **aucun des 80 modules n'a de gestionnaire d'erreur** —
vérifié, `onerror` est vide partout. Il y a 14 modules `ParseJSON` (202, 204, 206,
208, 210, 302, 304, 306, 402, 9998, 9997, 10010, 10014, 20016) : chacun peut arrêter
le run entier.

## Ce que le panneau INPUT du 208 a montré — et qui corrige mon hypothèse

J'avais supposé une troncature à `maxOutputTokens`. **C'est faux.** Chachou a ouvert
l'historique d'exécution : l'entrée du 208 contient trois morceaux collés bout à bout.

1. l'objet JSON **complet et valide** :
   `{"ju_win_rate":49,"syl_win_rate":54,"gil_win_rate":50,"alc_win_rate":51,`
   `"marees_win_rate":34,"best_archimage":"SYL","best_agent":"SYL","failed_pattern":…,`
   `"winning_pattern":…,"correction_directive":…,"correction_cible":"MAREES"}`
2. un fragment de 21 caractères : `ESPR_cible":"MAREES"}`
3. **le même objet complet, une seconde fois**, à l'identique.

Rien n'est tronqué : les deux copies sont entières. Le Sage Mémoire s'est **répété**.
Bout à bout, ces trois morceaux ne forment évidemment pas un JSON valide, et
ParseJSON s'arrête — à juste titre.

Le corps du 207 demande pourtant `"responseMimeType":"application/json"`, avec
`"temperature":0.01` et `"thinkingConfig":{"thinkingBudget":0}`. Le mode JSON garantit
la *forme* de ce que le modèle produit, il ne l'empêche pas d'en produire deux. Je ne
sais pas expliquer le fragment du milieu et je ne vais pas broder : ce qui est établi,
c'est que la réponse contient l'objet deux fois.

**Donc : ne pas toucher à `maxOutputTokens`.** Le point A de la fiche
`docs/maia/AA-208-sage-memoire-a-la-main.txt` est annulé — augmenter le plafond
n'aurait rien réparé, et aurait laissé croire que c'était réglé.
